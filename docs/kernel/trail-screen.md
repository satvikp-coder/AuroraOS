# Native Trail screen (Cycle 20, milestone E)

Read-only view of the audit ledger (`SCR_TRAIL`), reached from Index ("trail"); Home has no tile. Layout and strings follow `docs/agents/CYCLE18_UI_SPEC.md` section 2c with two documented deviations: the scroll buttons are labelled "Show newer" / "Show older" (clearer than the spec's wording) and the page size shrinks with the text scale (6 / 4 / 2 records at <=100 / <=150 / larger percent) so the card always fits above the dock.

* **Source:** `shell_run.c` hands the shell a COPY of the ledger state (`struct shell_trail_view`): health, up to 48 records, up to 32 durable grants. The screen holds no pointer into the ledgers and no system call reads or mutates either ledger. A failing or missing source shows "Trail: not available." and nothing else.
* **Health strings** (never a healthy claim for a damaged ledger): recording to disk / off, no disk / read-only disk / file unreadable / rollback found / held (another record file needs attention) / not available. The line is also logged as `shell: say ...` when it changes.
* **Rows** are constants and numbers only, newest first: Granted / Revoked (permission names from a fixed table), System started, Denied (kind and reason names from fixed tables) or Request done / not done, and "Unknown record kind K." for anything else. No user-typed text, no wall-clock time. Counts line "Changes: N. Denials: N." and "Saved permissions: N" with one line per durable grant (instance-bound grants are RAM-only and not shown as saved).
* **Controls:** only "Show newer", "Show older" (disabled at the ends) and "Home", plus the dock and the Glass Corner handle. Rows, grants and health text are labels: not focusable, not clickable. The view is re-read four times a second while the screen is open and repaints only if something shown changed.
* **Tests:** `tests/kernel-host/shell_trail_test.c` (42 checks, 10 mutants killed, 75..200% in both palettes, hostile views, 20,000 random inputs) and `tests/qemu/trail-ui-tests.sh` (real kernel and ledgers: records, 200%, no disk, read-only disk, rollback; real key and pointer events, pixels, the guest's own lines).
