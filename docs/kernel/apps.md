# Native application launcher and the Calculator (Cycle 21)

**What exists.** A bounded kernel registry (`kernel/proc/apps.c`, `kernel/include/apps.h`) of applications the shell can start on a person's request, a Calculator EL0 application (`tests/programs/calc.c`, pure arithmetic in `calc_core.h`), and an Index entry that launches it.

**Rules (all enforced in kernel code, tested):**
* Stable ids (`APP_CALCULATOR = 1`). The executable name, the identity (principal 601) and the UI capability come from the kernel table. The person, the shell UI and EL0 programs never name an executable or an identity; there is still **no system call that starts a program**.
* Launch uses the existing trusted loader (`launch_register` / `launch_app`): the executable must be INSTALLER-owned, not writable by others, CRC-verified and a valid ELF. No second loader. Nothing is parsed or executed from the person's input.
* One running instance, identified by (pid, generation); a reused pid never matches. A second launch while it runs is refused ("Already open. See Pages.") and creates nothing.
* When the process exits or faults the run loop reaps it: surfaces and queued events (`ui_sys_client_gone`), timers, Passport grants bound to the generation, a pending review, and the launcher's record (`apps_gone`) are dropped, so a relaunch is a fresh instance (QEMU test: display starts at 0, one new surface). The UI capability is a per-identity grant by kernel code and is re-derived from the table, not carried by the process; the Calculator holds no navigate, timer, settings or Passport right.
* Honest availability: listed "(not available yet)" unless the filesystem is mounted and the installer-owned `calc.elf` exists; a refused launch shows the kernel's reason in place of the Index hint.
* A launch is NOT a security decision about the program: it is unprivileged EL0 like every other client, confined by the existing UI protocol (surface quota, kernel placement, focus rules). Esc and Tab are never delivered to a client (they return focus to the shell), so the Calculator quits with **Q**.

**Calculator semantics.** Integers only, at most 9 typed digits, results limited to ±999,999,999,999 (else "Overflow"), division truncates toward zero, divide by zero is the "Divide by zero" error, left-to-right evaluation (2 + 3 × 4 = 20). Keys: digits (row or keypad), + - * /, Enter/=, Backspace, C or Delete (clear), Q (quit).

**Where the executable comes from.** The shipped kernel has no built-in programs; executables are installed on the AuroraFS disk by an installer step. `scripts/package-qemu.sh` is the repeatable local package (nothing is published): it builds the production kernel and every program listed in `tools/pkg/apps.list`, checks that the installed names equal the kernel registry's executable names (both ways), and runs `tools/pkg/mkdisk.c`, which links the REAL `afs.c` and `elf.c`: every ELF must pass the loader's own validator and the 24 KiB file limit, the installer's quota (8 files, 96 blocks) and name rules are enforced (never loosened), files are created owner-writable, filled, then sealed read-only for everyone (INSTALLER owner, never other-writable), and the finished image is re-mounted and each file is read back and compared. The output (`build/pkg`) holds `kernel.bin`, the pristine `aurora-fresh.img` template, `apps/*.elf`, `manifest.txt` (SHA-256, installed sizes and CRCs, tool versions) and two scripts: `fresh-install.sh` creates `data/aurora.img` and refuses to overwrite an existing disk without `--force`; `run.sh` boots on `data/aurora.img` and never creates or resets it, so saved data survives restarts. Builds are byte-identical. `tests/qemu/pkg-tests.sh` checks all of this and boots the packaged artifacts into the Calculator launch scenario. Verified on the WSL Linux development host only.

**Evidence.** Host: `calc_test` (28 checks + 200,000 random sequences against a `__int128` oracle), `shell_apps_test` (21). QEMU `tests/qemu/app-tests.sh` on the shipped kernel: launch from Index, kernel-chosen identity, Pages lists it, surface placed by the compositor, real keys 1 2 + 8 Enter = 20, 1/0 error, double launch refused, Q exits, cleanup, fresh relaunch; missing executable and missing disk launch nothing. The host/QMP can inject keys (no claim of protection against a malicious host).

## Notes (Cycle 22)

A second native EL0 application, `notes.elf` (`tests/programs/notes.c`, pure core `notes_core.h`), identity **602** from the kernel table. It holds only the UI capability and its own private files.

* **Editing (exactly what exists):** printable ASCII and newline, one cursor, Left/Right/Up/Down/Home/End, Backspace, Delete. At most 288 bytes and 8 wrapped rows of 36 columns; an insertion beyond either bound is refused, never truncated. **Not implemented:** selection, clipboard/paste, Unicode, input methods, undo. Ctrl+S saves, Ctrl+Q quits (Esc/Tab never reach clients). The status line always shows Unsaved changes / Saved / the reason a save failed.
* **Storage:** two alternating slot files `note.a` / `note.b` (owner-private, perm 3), format version 1: magic `ANTE`, version, length, sequence, CRC-32, body. Bytes after the declared length are ignored (a shorter rewrite cannot shrink a file). A save writes the slot that does not hold the current note, reads it back through the filesystem, decodes and compares; only then "Saved". A failed or torn write leaves the previous note intact. A damaged note, or one with a newer version, is never opened or overwritten (saving is switched off and the status says why). Files owned by another principal that happen to be visible are treated as absent (Notes checks the owner on every lookup). Read-only disk, full disk/quota, missing disk and an uncertain write each produce their own message; none says "Saved". Not atomic across files and not claimed to be.
* **Evidence:** host `notes_test` (54 checks: bounds, wrapping, cursor, key map, every truncation and single-bit corruption refused, 200,000 random byte strings, 600,000 random edit operations against an oracle). QEMU `tests/qemu/notes-tests.sh` on the packaged kernel and disk: launch from Index, type "AuroraOS is my independent operating system.", Ctrl+S, quit, reopen; then three separate emulator restarts on the same disk (exact text; shorter text; longer text), read-only disk, no disk, corrupt, newer-version and foreign-owned note.
