# AuroraOS QEMU Emulator Beta Package Build Documentation

## Overview

This document describes the reproducible build process, package format, installation procedures, and verification methods for the AuroraOS QEMU Emulator Beta distribution. The package is designed for developers and early adopters who want to run AuroraOS in QEMU without physical ARM64 hardware.

---

## 1. Reproducible Build Process

### 1.1 Deterministic Kernel Binary (`kernel.bin`)

The AuroraOS kernel build is fully deterministic when built with the standard toolchain:

```bash
# Standard production build
AURORA_PRODUCTION=1 ./build.sh
```

**Determinism guarantees:**
- Fixed compiler flags: `-O2 -ffreestanding -nostdlib -fno-builtin -fno-stack-protector -fno-pic -fno-strict-aliasing -fno-tree-loop-distribute-patterns`
- No embedded timestamps, build paths, or host-dependent data in the output binary
- Linker script (`kernel/linker.ld`) produces identical layout across builds
- `objcopy -O binary` produces identical raw binary from identical ELF

**Verification:**
```bash
# Build twice and compare
AURORA_PRODUCTION=1 BUILD_DIR=build/1 ./build.sh
AURORA_PRODUCTION=1 BUILD_DIR=build/2 ./build.sh
sha256sum build/1/kernel.bin build/2/kernel.bin
# Output must be identical
```

### 1.2 Package Build Script (`scripts/package-qemu.sh`)

The package script creates a complete, self-contained distribution:

```bash
PKG_DIR=/path/to/output ./scripts/package-qemu.sh
```

**What it produces:**
```
<PKG_DIR>/
├── kernel.bin              # Raw kernel binary (deterministic)
├── kernel.elf              # ELF with symbols (for debugging)
├── kernel.map              # Linker map file
├── aurora-fresh.img        # Pristine disk image template (2048 sectors)
├── apps/
│   ├── calc.elf            # Calculator app (~20 KiB)
│   ├── notes.elf           # Notes app
│   └── files.elf           # File browser app
├── manifest.txt            # SHA-256 checksums of all files
├── verify-bundle.sh        # Integrity verification script
├── fresh-install.sh        # Creates data/aurora.img from template
├── run.sh                  # Launches QEMU with the installed disk
└── data/                   # Created by fresh-install.sh (not in package)
    └── aurora.img          # User's persistent disk image
```

**Build determinism:**
- Two invocations with different `PKG_DIR` produce **byte-identical** artifacts
- `manifest.txt` contains SHA-256 of every file for verification
- Tested in `tests/qemu/pkg-tests.sh` (lines 13-16)

### 1.3 Required Toolchain

| Component | Version | Notes |
|-----------|---------|-------|
| `aarch64-linux-gnu-gcc` | 11+ | Freestanding, no libc |
| `aarch64-linux-gnu-as` | 2.35+ | |
| `aarch64-linux-gnu-ld` | 2.35+ | |
| `aarch64-linux-gnu-objcopy` | 2.35+ | |
| `qemu-system-aarch64` | 7.0+ | TCG mode (no KVM required) |
| `sha256sum` | coreutils 8.32+ | For manifest/verification |
| `python3` | 3.8+ | For app_check.py (test automation) |

## 2. Package Manifest Format

### 2.1 `manifest.txt` Structure

```
<sha256>  kernel.bin
<sha256>  kernel.elf
<sha256>  kernel.map
<sha256>  aurora-fresh.img
<sha256>  apps/calc.elf
<sha256>  apps/notes.elf
<sha256>  apps/files.elf
```

- One line per file: `<64-hex-chars>  <relative-path>`
- Space-space (two spaces) separates hash from path
- Paths are relative to package root
- Generated by `scripts/package-qemu.sh` during packaging

### 2.2 Disk Image Format (`aurora-fresh.img`)

- **Format:** Raw disk image (AuroraFS v1)
- **Size:** 2048 sectors × 512 bytes = 1,048,576 bytes (1 MiB)
- **Contents:** Superblock + 3 installer-owned applications (calc, notes, files)
- **Immutability:** Never modified by `fresh-install.sh` or `run.sh`; used as template only
- **Filesystem:** AuroraFS (custom, CRC-protected, read-only-safe mount)

### 2.3 Application ELF Format

| Property | Requirement |
|----------|-------------|
| Architecture | AArch64 (ARM64) |
| Type | `ET_EXEC` (executable, not shared object) |
| Endianness | Little-endian |
| Maximum size | 24 KiB (24,576 bytes) |
| Load address | 0x4000_0000 (enforced by kernel loader) |
| Stack | 16 KiB (provided by kernel) |
| Capabilities | Declared in ELF notes (e.g., `SYS_UI`, `SYS_FS`) |

## 3. Install/Run Documentation for Fresh Users

### 3.1 Quick Start (Linux / WSL)

```bash
# 1. Clone and enter repository
git clone https://github.com/your-org/AuroraOS.git
cd AuroraOS

# 2. Build the package (deterministic)
AURORA_PRODUCTION=1 PKG_DIR=./aurora-pkg ./scripts/package-qemu.sh

# 3. Enter package directory
cd aurora-pkg

# 4. Create your persistent disk (one-time)
./fresh-install.sh

# 5. Run AuroraOS
./run.sh
```

### 3.2 Quick Start (Windows WSL2)

```powershell
# In WSL2 Ubuntu/Debian:
sudo apt update && sudo apt install -y \
  gcc-aarch64-linux-gnu qemu-system-arm \
  python3 sha256sum make

# Then follow Linux steps above
```

**WSL2 notes:**
- Use `qemu-system-aarch64` (not `qemu-system-arm64` on some distros)
- `-display none` works for headless; for GUI use `-display gtk` or `-display sdl`
- File paths: use `/mnt/c/...` for Windows files, native paths inside WSL

### 3.3 Command Reference

#### `fresh-install.sh`
```bash
./fresh-install.sh              # Creates data/aurora.img from template (fails if exists)
./fresh-install.sh --force      # Overwrites existing data/aurora.img
```

- **Never modifies** `aurora-fresh.img` (the template)
- Creates `data/aurora.img` as a **copy** of the template
- Refuses to overwrite without `--force` (protects user data)

#### `run.sh`
```bash
./run.sh                        # Boot with graphical display (ramfb)
./run.sh -display none          # Headless (serial only)
./run.sh -display gtk           # GTK display (Linux)
./run.sh -display sdl           # SDL display (cross-platform)
```

- **Never creates or resets** the disk
- Requires `data/aurora.img` to exist (run `fresh-install.sh` first)
- Passes additional args to QEMU (e.g., `-monitor stdio`)

#### `verify-bundle.sh`
```bash
./verify-bundle.sh              # Verifies all files against manifest.txt
```

- Exits 0 on success, nonzero on any mismatch
- Reports which file(s) failed verification
- States limitation: "checksums detect accidents and partial tampering; authenticity needs a signature checked against a key held elsewhere"

### 3.4 Directory Layout After Install

```
aurora-pkg/
├── kernel.bin              # (from package)
├── kernel.elf
├── kernel.map
├── aurora-fresh.img        # (from package, read-only template)
├── apps/
│   ├── calc.elf
│   ├── notes.elf
│   └── files.elf
├── manifest.txt
├── verify-bundle.sh
├── fresh-install.sh
├── run.sh
└── data/                   # (created by fresh-install.sh)
    └── aurora.img          # YOUR persistent disk (modify, backup, copy)
```

**Backup your data:** Copy `data/aurora.img` to preserve your files, settings, and Trail across package updates.

## 4. Known Limitations

### 4.1 No Offline Speech Recognition
- **Status:** Not implemented in beta
- **Impact:** Voice commands, dictation, and speech-to-text unavailable
- **Workaround:** Text input via virtio keyboard/tablet only

### 4.2 No Physical Hardware Support
- **Target:** QEMU `virt` machine (ARM64) only
- **Unsupported:** Raspberry Pi, Apple Silicon, physical ARM64 boards
- **Drivers:** Only `virtio-blk`, `virtio-input`, `virtio-snd`, `virtio-mmio`, `ramfb`, `fwcfg`
- **No:** GPU acceleration, GPIO, I2C, SPI, UART (beyond PL011), USB, WiFi, Bluetooth

### 4.3 No KVM / Hardware Acceleration
- **Mode:** TCG (Tiny Code Generator) only
- **Performance:** ~10-50x slower than native; suitable for functional testing only
- **SMP:** Single vCPU (`-smp 1`) — multi-core not tested

### 4.4 Filesystem Capacity
- **Disk size:** Fixed 1 MiB (2048 sectors)
- **Max files:** ~8 installer + ~8 user files (inode table limit)
- **Max file size:** ~24 KiB per file (loader limit)
- **No:** Dynamic resize, partitions, multiple disks

### 4.5 Audio
- **Output:** virtio-snd → QEMU audio backend (pulse/pipewire/alsa/coreaudio)
- **Input:** Not implemented
- **Quality:** 48 kHz stereo PCM; no codec support

### 4.6 Networking
- **Status:** Not implemented in beta
- **Impact:** No internet, no network services, no OTA updates

### 4.7 Persistence Model
- **Trail (audit log):** Written to disk on every boot
- **Settings:** Stored in AuroraFS (survives reboot)
- **No:** Encryption at rest, secure boot, measured boot

## 5. Package Integrity Verification

### 5.1 Manifest Verification (`verify-bundle.sh`)

```bash
./verify-bundle.sh
```

**What it checks:**
1. Every file listed in `manifest.txt` exists
2. SHA-256 of each file matches the recorded hash
3. No extra files in `apps/` beyond those listed
4. `kernel.bin`, `aurora-fresh.img`, and all `apps/*.elf` present

**Output on success:**
```
verify-bundle: all checksums match
verify-bundle: NOTE: checksums detect accidents and partial tampering; authenticity needs a signature checked against a key held elsewhere
```

**Output on failure:**
```
verify-bundle: MISMATCH: apps/calc.elf (expected abc123..., got def456...)
verify-bundle: FAILED
```

### 5.2 Reproducibility Verification

```bash
# Build twice independently
PKG_DIR=/tmp/pkg1 ./scripts/package-qemu.sh
PKG_DIR=/tmp/pkg2 ./scripts/package-qemu.sh

# Compare all artifacts
cd /tmp/pkg1 && sha256sum kernel.bin aurora-fresh.img apps/*.elf > /tmp/h1.txt
cd /tmp/pkg2 && sha256sum kernel.bin aurora-fresh.img apps/*.elf > /tmp/h2.txt
diff /tmp/h1.txt /tmp/h2.txt
# No output = identical
```

### 5.3 Boot-Time Integrity (Kernel Self-Check)

The kernel verifies the disk on every mount:
- Superblock checksum (CRC-32)
- Inode checksums (CRC-32 per inode)
- File data CRC-32 (per 512-byte sector)
- ELF validation on load (magic, architecture, capabilities, size, W^X, kernel VA exclusion)

**Recovery behavior:** On any corruption, the kernel:
1. Reports the specific failure reason via serial console
2. Refuses to mount the filesystem
3. Boots to shell with `settings store=none` (session-only)
4. **Never writes** to a disk it could not mount

## 6. Supported Host Platforms

| Platform | Status | Notes |
|----------|--------|-------|
| **Linux (x86_64)** | ✅ Fully supported | Native QEMU TCG; best performance |
| **Windows 10/11 (WSL2)** | ✅ Fully supported | Ubuntu/Debian/Arch in WSL2; use `-display gtk` or `-display sdl` for GUI |
| **macOS (Apple Silicon)** | ⚠️ Untested | QEMU TCG works but `aarch64-linux-gnu` toolchain must be installed (e.g., via Homebrew) |
| **macOS (Intel)** | ⚠️ Untested | Same as Apple Silicon; Rosetta 2 may add overhead |
| **Linux (ARM64 native)** | ✅ Works | Can use KVM (`-enable-kvm -cpu host`) for near-native speed; not tested in CI |
| **FreeBSD / NetBSD** | ❌ Not supported | QEMU available but build toolchain not validated |

### 6.1 Minimum Host Requirements

| Resource | Minimum | Recommended |
|----------|---------|-------------|
| CPU | 2 cores | 4+ cores |
| RAM | 2 GiB | 8+ GiB |
| Disk | 500 MiB | 2 GiB |
| OS | Ubuntu 22.04+, Debian 12+, Fedora 38+, Arch | Latest LTS |

### 6.2 Known Host Issues

| Issue | Platform | Workaround |
|-------|----------|------------|
| `qemu-system-aarch64` not found | Some Linux distros | Package name may be `qemu-system-arm` (Debian) or `qemu-system-aarch64` (Fedora/Arch) |
| GTK display fails | WSL2 without VcXsrv/WSLg | Use `-display sdl` or `-display none` |
| Audio silent | WSL2 / some Linux | Ensure PulseAudio/PipeWire running; try `QEMU_AUDIO_DRV=pa` |
| Build fails: `aarch64-linux-gnu-gcc` not found | All | Install `gcc-aarch64-linux-gnu` (Debian/Ubuntu) or `aarch64-linux-gnu-gcc` (Fedora/Arch) |

## 7. Updating the Package

### 7.1 For Users

```bash
# 1. Backup your data
cp -r aurora-pkg/data ~/aurora-backup-$(date +%Y%m%d)

# 2. Pull latest source
git pull

# 3. Rebuild package to new directory
AURORA_PRODUCTION=1 PKG_DIR=./aurora-pkg-new ./scripts/package-qemu.sh

# 4. Copy your data disk
cp aurora-pkg/data/aurora.img aurora-pkg-new/data/

# 5. Verify
cd aurora-pkg-new && ./verify-bundle.sh

# 6. Run
./run.sh
```

### 7.2 For Developers (Testing Changes)

```bash
# Non-production build (includes self-test hooks)
BUILD_DIR=build ./build.sh

# Quick boot test
./run-qemu.sh build/kernel.bin

# Package test suite
./tests/qemu/pkg-tests.sh
```

## 8. Troubleshooting

### 8.1 Boot Hangs / No Output

```bash
# Check serial log
./run.sh -display none -serial file:boot.log
cat boot.log
```

### 8.2 "run: no disk" Error

```bash
# Forgot fresh-install.sh
./fresh-install.sh
./run.sh
```

### 8.3 "filesystem is CORRUPT" on Boot

- Your `data/aurora.img` is damaged
- Restore from backup or re-run `./fresh-install.sh --force` (loses data)

### 8.4 Verify-Bundle Fails

```bash
# Re-download / rebuild package
# If you modified files intentionally, update manifest.txt:
sha256sum kernel.bin aurora-fresh.img apps/*.elf > manifest.txt
```

## 9. Security Considerations

- **No authenticity:** Checksums only detect corruption/tampering; they do not prove origin
- **No encryption:** Disk image is plaintext; anyone with file access reads all data
- **No sandboxing:** EL0 apps share address space isolation only; no syscall filtering beyond capability checks
- **TCG only:** No hardware-enforced isolation; host kernel compromise = guest compromise
- **Intended use:** Development, testing, evaluation — **not** for sensitive data
