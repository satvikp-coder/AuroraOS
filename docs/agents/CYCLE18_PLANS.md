# Cycle 18 implementation plans (A timer/Clock, B Passport+Trail, C trusted review)

Produced by a read-only review pass against main at 4a783f8. Verify every cited symbol still exists before relying on it. QEMU virt only; one QEMU suite at a time; kernel and UI edits never in one PR; syscalls 10..40 stay -ENOSYS (42 is free).

## Verified facts
* Time: `timer_count()` = CNTPCT_EL0, `timer_freq()` = CNTFRQ_EL0 (62,500,000 Hz in QEMU). `SYS_TICKS` only advances while the scheduler runs: not a clock. The shell loop polls at 100 Hz idle and 1000 Hz inside slices.
* `ui_sys.c` per-pid event queue: depth 4, events <= 16 bytes, drop-oldest, `q_push` is static. The only exit hook is `reap()` in `shell_run.c` (it calls `ui_sys_client_gone`); `init_run` (`launch.c`) destroys without a hook.
* AuroraFS: 8 files / 96 blocks per owner, 32 files total, whole-file copy-on-write, `fs_write` never shrinks a file, `FS_ERO` comes from `blk_readonly()`, `FS_EUNCERTAIN` unmounts. The production mount happens in `fstest_run()` after `shell_boot_draw()`/`broker_init()`, so attach storage in `shell_loop` beside `settings_load`.
* Principals: 0x7F000001 installer, ...02 settings, ...03 shell; ...04/...05 unused. `next_gen` restarts at 1 every boot.
* No toast, no modal except About, no production disk, no EL0 Clock, no launcher outside `AURORA_SHELL_CLIENTS` builds.

## PLAN A: timer service -> native Clock and Aura timer
* **A1** (PR #96): `TS_PER_OWNER = 2`, `TS_E_QUOTA`.
* **A2 core kernel:** `SYS_TIMER = 42` (`proc.h`, `sched.c` do_syscall) and `kernel/proc/timersys.c/.h`. Ops START(ms)->id, CANCEL(id), QUERY(id, uva[16]: u8 state, 7 zero, u64 remaining LE), RELEASE(id), NOW. Errors `AE_TM_BASE (-400) + TS_E_*`. Kernel-granted capability (8 slots; refuses 0, NONE and 0x7Fxxxxxx principals). `now_ms` from `timer_count/timer_freq`, overflow-safe. `timersys_tick()` in the shell loop polls and posts `UIP_EVENT_TIMER = 0x85` `{1,0x85,0,0,0,0,0,0,id,state,0,0}` through a new exported `ui_sys_post` (a `notified[]` array remembers delivered completions). `reap()` calls `timersys_owner_gone(pid, gen)`. Check `user_writable` before any state change. QEMU `timer-tests.sh` scenarios: basic (never early), hostile (999 ms, 24 h + 1, third timer, foreign id, kernel pointer, op 99, no grant, 20,000 start/cancel flood while Tab still responds), exit/fault (owner gone drops timers; a new instance in the same pid cannot see old ids), starved (done < 1 s late with two spinners).
* **A3 pure:** append `AK_START_TIMER`, `AR_TIMER_FORM`, `BPR_NO_TIMER`; intent target = unit (0 sec, 1 min, 2 hour), `AA_ABS` count, risk 0 (S0: bounded, not persisted, owner-cancellable, dies with its owner); grammar only when `caps->timer`; `BP_RIGHT_TIMER 0x4`; `bp_env.timer_service/timer_start`; `aura_execute_timer` returns 1 only if `timer_start` returned >= 0; `aura_run_queued` must check the per-kind right. Update the mutators (never delete a mutant).
* **A4 shell:** `CAPS = {1,1,0,0,0}`; `timer_start = timersys_start_for`, which reads back with `tsvc_query` before reporting Done; shell-owned completion shows a compositor toast ("Timer finished") through a new `shell_notice` on `UI_LAYER_TOAST`; the "start a timer" expectations in `aura_s0_check.py` and `aura_ui_check.py` change (state it in the PR; replace, do not delete).
* **A5 EL0 Clock:** `tests/programs/clock.c` (uptime h:mm:ss from NOW, never a wall-clock time; a timer line; keys), launch entry + grant, QEMU `clock` scenario. A production launcher is a later PR.
* Do not: use SYS_TICKS or frame counts as time; clamp durations; report Aura success without the read-back; grant `BP_RIGHT_TIMER` by default; touch syscalls 10..40.

## PLAN B: Passport + Trail wiring
* **B0** (PR #88): instance-bound grants are RAM-only; separate mutation/denial rings; `passport_peek`; per-principal quota; `passport_drop_instance`; `PP_TIMER`; trail decode rejects seq 0/0xFFFFFFFF; `trail_head`; reserved trail kinds 12 grant, 13 revoke, 14 boot.
* **B1 reserved principals:** `PRINCIPAL_PASSPORT 0x7F000004`, `PRINCIPAL_TRAIL 0x7F000005`, `PRINCIPAL_IS_RESERVED`; refuse reserved principals in `launch_register`, `proc_set_principal`, `proc_create_elf` and `ui_sys_grant`; grep the tests for 0x7F first.
* **B2 storage (`kernel/ui/ledger_store.c`):** files `passport.v1` (owner PASSPORT, 2 blocks), `anchor.v1` (32 bytes, 1 block), `trail.v1` (owner TRAIL, 4 blocks). Container = u32 length + image + zero padding (needed because `fs_write` never shrinks). Create/write as the owner with owner-only permissions (the `settings.c persist()` pattern). Anchor `ANCH` + next_seq + trail_head + mseq + crc is written AFTER the trail: equal = OK, one record ahead = repair, behind or mismatch = rollback (trail unhealthy, appends refused). Replacing all files together offline is undetectable on QEMU virt (no hardware counter): document it. API `ledger_attach` (after `settings_load`), `ledger_pp_grant/revoke`, `ledger_trail_append`, `ledger_passport_ok/trail_ok`. Behaviour: no disk -> RAM table, `env.passport/trail = 0`, S0 and timers still work; read-only -> loaded for checks, mutations refused, flags 0; corrupt or newer -> empty denying table, file left untouched, flags 0; a runtime store failure -> flag sticks at 0 and the action does not run. QEMU `ledger-tests.sh`: fresh, persist, rodisk, nodisk, corrupt, rollback, quota.
* **B3 broker:** `lookup()` derives rights only from `passport_peek` (delete `grant_gen/grant_rights`); `broker_grant_navigate` becomes a RAM-only gen-bound kernel grant (no disk needed); `reap()` calls `passport_drop_instance`; `env.passport/trail` come from the ledger; S1 additionally needs `env->trail` (checked after `review_path`); add mutant "S1 does not need Trail".
* **B4 shell:** boot log lines and a read-only `SCR_TRAIL` screen (last 8 records, durable grants, mutation/denial counts, health). No EL0 syscall reads or mutates either ledger.
* Do not: persist gen-bound grants; overwrite an unparsable file; own files as principal 0; treat FNV as tamper-proof; set a flag to 1 on a read-only disk.

## PLAN C: trusted review and S1
* **C1 pure `review.c`:** one review at a time; tickets never reused; states IDLE/OPEN/ARMED; `rv_attention` arms only after 600 ms, approval window 10 s, timeout 60 s; `rv_digest` over an explicit little-endian serialisation of every intent field + pid + gen + nonce + prior + next; `rv_approve` consumes the ticket before returning; `rv_verify` re-checks the intent at execution. Tests: replay, early/late approve, changed byte, requester gone, a 30,000-step model.
* **C2 compositor modal + secure attention:** `build_review/review_scaled` modelled on `build_about/about_scaled` with `UI_LAYER_SCRIM` + `UI_LAYER_MODAL` and `ui_modal_push`; a compositor-only strip "AuroraOS secure review"; requester name from the kernel; focus defaults to Cancel; Approve disabled until armed; Esc declines. Add `|| review_open` at every `about_open || corner_open` site. Secure attention = Ctrl+Alt+Delete handled first in `route_client`, never delivered to clients, arms the review. Honest limits: the host/QMP can inject it; the kernel shell is the trusted base; with no keyboard there is no review path and S1 stays unavailable.
* **C3 S1 executor** (needs B3): read the prior value through the registry as the shell principal; resolve relative text size to a step in {75,100,125,150,175,200}; open the review; on approval re-validate, re-read prior, append the PRE Trail record (it must return OK or nothing runs), `store->set`, verify with `get`, apply, append the POST record. Messages: "Done: Set text size to 125%. Receipt #N."; theme "Saved ... Not drawn yet (no dark theme)." Only the shell holds `BP_RIGHT_SETTINGS`.
* **C4 honest Undo:** offered only when the trail is healthy, the newest POST record is DONE, the preceding PRE record supplies the prior value and the registry still equals the recorded new value; it runs the same review path.
* **C5 hold-to-confirm** (pure `hold.c`, demo only; `env.hold_input` stays 0): 1500 ms hold on the monotonic counter, cancel on release, leaving the control, another key, a focus or modal change; repeat events ignored; no animation.
* Do not: let any client message, syscall or focus event answer a review; approve on Enter with default focus; run an effect before the PRE record; give the shell `CAP_SET_SYSTEM`; set `review_path`/`hold_input` to 1 before their tests exist; claim a dark theme is applied.
